# Core／CLI 验证状态

本页区分已取得的证据与目标环境尚需完成的检查。旧版测试不能替代新安装包的原生验收。按[开发指南](../build/DEVELOPMENT.md)选择受影响的测试，不必每次跑全量套件。

## 已有证据

配置与真实生成目录夹具覆盖多文件来源、保存重载、周期规则重新匹配新增内容、精确选择、排除项、一次性计划消费及部分执行回执。文件系统失败不能自动重放删除，目录移动与恢复冲突不能覆盖新内容。Linux 原生授权、登录撤销、调度与 Btrfs Snapper 的认证、保护状态和空间净变化已有实际环境验证；这些是对应环境的证据，不代表所有卷与平台组合已通过。

最近 Windows 反馈修复通过 1 项文件系统授权对账测试与 10 项 CLI 清理输出测试。18 个共同权限失败在人类输出中只解释一次，最多列 5 个位置，JSON 仍保留全部。组件未启动、执行结果未确认和部分已发生效果分别保留。

Docker 的 14 项插件测试与 Core 配置→探测→扫描→确认→精确执行夹具已通过；实际本机只做过只读探测／扫描，没有据此执行真实 Docker 清理。Go／Cargo／npm 的 Linux 夹具覆盖独立启停、发现、保存规则复用和执行结果。跨编译只证明目标代码可编译。

## 计量与显示约定

普通内容的逻辑大小与快照卷可用空间净变化分开。Snapper `#0 current` 显示“当前系统／不适用”，无历史快照时显示无可清理快照；只有真正计量失败才归为未知。受保护项可见但不可选，快照不计入普通文件未知项。共享块、并发磁盘活动及 Docker 共享层不能简单相加为实际释放量。
